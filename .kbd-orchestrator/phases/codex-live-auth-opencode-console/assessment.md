# Assessment of live Codex auth, OpenCode and the embedded console

**2026-11-19 · openai-proxy · baseline `921868e` · stage Assess**

A completed `codex login` cannot update the running proxy today. Startup copies the credential, backend URL and wire profile into application state. The OpenCode plugin also reads and caches credentials independently. Delivering the requested behavior requires a single credential owner per user and a request-time snapshot shared by every transport. The repository already has REST chat, MCP, ACP and AG-UI entry points. It still needs two SDK-backed chat drivers, a V2 plugin, the embedded React application and an authenticated settings API.

## Identity and entitlement

Use the Codex identity selected by the service operator. Define explicit path overrides, `CODEX_HOME`, default home, file/keyring/auto and environment API key precedence. Today an explicit path can still fall through to keyring on read or parse failure. The plugin and setup code have narrower parsers than Rust. A partial write or an unreadable store must never select an unrelated account. Distinguish signed out, transient read failure, external credential ownership, API key, expired/revoked grant and healthy session. A signed-out start should leave authorized recovery available.

For managed ChatGPT login, investigate delegating refresh to the credential-owning Codex App Server through `account/read` with `refreshToken: true`. Its response conveys account information. Reread the authoritative store after success. External-token mode routes renewal to its owning host. API keys have no OAuth refresh. File mode needs parent-directory observation across atomic renames plus reconciliation after missed events. Keyring-only logins need an independent bounded reconciliation trigger. Plugin-initiated login should request reconciliation once login succeeds. Publish bearer, account header, generation, profile, backend and visible models together. Cancel or discard an old refresh after logout/account switch. Use single-flight refresh per identity, bounded retry/backoff, and distinguish authorization errors from rate limits. Never replay streamed output or tool effects. [Codex App Server](https://developers.openai.com/codex/app-server/)

The proxy CLI has two lifetimes. Default invocation and `serve` (HTTP, ACP stdio or MCP stdio) all enter `run_server` and retain the startup identity. Install the shared credential manager before either stdio early return and exercise an external login against each running mode. The one-shot `setup opencode` command independently reads only a top-level `access_token` at the default home path to choose the model list. Verify that a fresh setup after login reflects the service's effective identity, including a nested store or a custom home, without persisting a bearer. `setup mcp/config`, `config show/path` and `skills` exit before server auth initialization. [CLI dispatch](../../../src/main.rs) · [OpenCode setup](../../../src/cli/setup.rs)

Trace request-time use in REST, AG-UI, ACP, both MCP transports, model discovery and the optional embedding client. Embeddings currently snapshot an API key at startup and require their own entitlement. User-owned credentials may only go to their intended upstream. Check this explicitly when a custom backend URL is configured. Show generation, source type, update time and remediation with secrets redacted. In Compose the single-file bind can retain an old inode after host login renames the file. Designate one writer and test host-owned credentials from inside the container. A directory mount or host broker requires an explicit access boundary. The existing runtime image has no Codex CLI/Node or host keyring integration. [Container configuration](../../../docker-compose.yaml)

The Pro requirement is one consenting subscriber using their actual Codex allowance, with observable provider and model results. A plan string or a fixture is insufficient evidence of billing or access. OpenCode's own ChatGPT authorization does not automatically grant a different application access. Confirm the supported sign-in path for the selected integration and record a separately authorized real-account check before claiming entitlement. Shared deployments need per-user identity and consent, quota isolation, and an explicit unavailable state when either is absent. No implicit fallback to an operator subscription or separately billable API key. The checked-in package uses `@opencode-ai/plugin` and V1 hooks. Verify local and packaged loading, provider/model discovery, preservation of existing user settings, and a streamed turn through the Codex SDK. Do not infer active precedence from file existence. The REST client should select either SDK for a new conversation and see the effective driver. Persist the owner, driver, approved working directory and native conversation ID. Codex SDK uses thread start/resume and `runStreamed` with an abort signal. Convert cumulative item snapshots to incremental output once. Only offer interactive approvals if the chosen Codex integration exposes them. The OpenCode SDK starts an in-process runtime, creates sessions and admits prompts asynchronously. Subscribe before submitting, filter events by session, propagate explicit interruption and scope permission replies. Remote server attachment uses a separate client. Preserve errors, usage when available, cancellation, tool outcomes and session isolation across both. Resolve persistence explicitly for OpenCode's default in-memory store. Select one tool executor per turn and prevent an OpenCode-backed turn from routing through the proxy back into itself. The published service needs a defined SDK runtime even when its web assets are fully embedded. ## Console and protocols

Build the React 19/Vite 8 app with a locked dependency graph through Cargo's build script, embed the compiled assets, and serve chat and settings with correct MIME, cache and deep-link behavior. Keep API errors and missing assets observable. Verify an incremental asset edit, a failed frontend build, a clean binary outside the checkout and the release container. Local owner and shared chat/admin flows require keyboard-accessible streaming, stop, partial output, useful reconnect and error states, and server-enforced privileges. Use the existing Impeccable brief, UI UX Pro Max and shadcn/ui component guidance. Screen-reader feedback must remain usable during streaming and dynamic surface updates.

Implement a versioned AG-UI envelope for structured A2UI alongside text and explicit failures. Pin compatible schemas and a React renderer. Buffer a complete typed message before validation, allow only locally registered catalog entries and bounded state, and isolate surface state by owner, conversation, run and surface ID. Render create, component/data update and deletion. Keep unrelated text and the last valid surface usable after malformed, oversized or unsupported input. Raw JSON in assistant text stays text. Authorize a user action against its originating surface and session on the server. Model-provided components cannot invoke admin settings, arbitrary code or unrestricted URLs. A2A advertises discovery separately. [A2UI messages](https://a2ui.org/reference/messages/) · [Catalogs](https://a2ui.org/concepts/catalogs/)
