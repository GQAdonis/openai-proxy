# Engineering analysis of live Codex auth and the embedded console

**Phase** `codex-live-auth-opencode-console` · **Assessment commit** `d16c262` · **Research date** 2026-11-19

Use Codex as the owner of managed ChatGPT credentials. Put a generation-aware credential resolver in front of all proxy transports and run the two chat SDKs behind a server-side driver interface. The OpenCode plugin should register a provider with an explicit Codex destination. The console can ship inside the Rust binary and use the published AG-UI client and A2UI React renderer. The SDK drivers still require an execution runtime in deployments that enable them.

This is a specified stack. The team checked Codex CLI 0.169.0 and OpenCode 2.3.0 on the service host. The [candidate set](library-candidates.json) contains 14 decisions and seven areas of custom work. The [assessment](assessment.md), [settings inventory](settings-inventory.md) and [11 candidate scenarios](scenario-candidates.md) define the scope. The timing and compatibility targets below remain proposals for Spec.

## Credential ownership, refresh and external login

**Adopt and adapt candidates 001–003. Reject 013.** In the pinned App Server, a forced `account/read` can return account metadata after a failed refresh. Its auth manager can reuse a newer credential already in the same account's store. It rejects certain account mismatches, and a long-lived manager does not automatically adopt an external login. Compare-before-save protects the store after an exchange, but the network exchange happens before the disk update. Treat an interrupted refresh as indeterminate. [Account read implementation](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/app-server/src/request_processors/account_processor/workspace_routing.rs#L259-L294) · [Guarded refresh](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/login/src/auth/manager.rs#L3455-L3517) · [Storage commit](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/login/src/auth/manager.rs#L3759-L3789)

| Trigger | Proposed service behavior | Observable outcome |
|---|---|---|
| Startup, explicit reload or successful plugin login | Resolve the configured owner, selected store and current login first. Watch the credential file's parent across atomic rename. Treat notifications as hints, debounce and reconcile. Periodically check the authoritative store for missed events and keyring-only changes. | Expose redacted status, generation, source, age and last reconciliation. New requests pick up a confirmed login with the PID unchanged. Initial targets are 2 s for file events and 30 s for reconciliation with a healthy store. |
| Managed credential reaches expiry or an eligible request receives an authentication failure | Coalesce work for the same principal and generation. Reread first. Ask the owning App Server to refresh when necessary. Reread after it returns and verify a usable, correctly scoped credential or obtain success through the owning runtime. | Mark renewed only on evidence of freshness or successful authenticated use. For an already fresh generation record reuse. Back off on transient failure, classify revocation as sign-in required and preserve quota errors. |
| Same-account token replacement, account switch, logout or invalid read | Publish a coherent snapshot of auth, account, trusted destination, wire profile and model view. Invalidate old generation work and retire stale helpers on account switch or logout. Distinguish a transient write from a confirmed removal, and stop using a credential after expiry or confirmed invalidation. | New turns use the new generation only after publication. An old refresh completing late cannot resurrect a login. Previously emitted bytes and side effects are never replayed. A turn may retry once only before an externally visible effect and when the operation is known safe. |
| Other credential types | External-token integrations ask their declared owner for renewal. API keys have no OAuth refresh. Embedding credentials are a separate API-key case. Explicit custom paths must resolve to their intended owner. Make incompatible store or custom-upstream combinations unavailable. | The UI tells the owner whether refresh, reload or login is appropriate. A failed read cannot silently select an unrelated keyring, inherited API key or paid fallback. |

Start the resolver before HTTP, MCP stdio or ACP stdio branches return. Apply the same resolution to REST, AG-UI, MCP tools, ACP, model discovery and one-shot `setup opencode`. Check a request's principal again before resuming native sessions. Trusted upstreams must match the credential type. In shared deployments require an authenticated user's own identity, isolated Codex home and workspace. An operator configures the service and can see redacted state. Administrative access does not grant use of another subscriber's account.

**Deployment choice.** Prefer a host-side Codex owner for host-managed login/keyring; the container subscribes to authenticated reconciliation or forwards work to that owner. A dedicated file-backed deployment may instead run its own Codex owner with a private writable credential directory visible across renames. Do not rely on the existing single-file bind or mount a whole personal Codex home into a shared worker. Distinguish file, keyring, auto, ephemeral and platform-specific encrypted storage. For stores without a verified authorized reader, the same-owner SDK path can still be considered, but direct bearer forwarding must report unavailable. During Spec choose one write owner per store, including the policy for CLI and SDK processes refreshing concurrently. A service-local mutex cannot serialize an independently running CLI. Preserve the current direct REST entry for compatible configurations. ## OpenCode V2 plugin, Pro and SDK conversations

**Adopt and adapt 003–005. Reference 006. Reject 014.** Pin the native V2 plugin to `@opencode/plugin@2.3.0`. Export its server entry using `Plugin.define`, warm the permitted model catalog, then register via the synchronous `ctx.provider.transform`. Preserve pre-existing provider ownership and user model overrides. Use a proxy-scoped connection for the Codex-targeted provider and reload provider metadata when the owner/account changes. Keep upstream login credentials out of the plugin config and shell environment. A plugin login completion is an explicit reconciliation hint. Verify the global install from outside the checkout and the packaged export using the actual V2 host. [Plugin API](https://github.com/anomalyco/opencode/blob/v2.3.0/services/site/src/docs/content/build/plugins/server.mdx) · [Configuration precedence](https://github.com/anomalyco/opencode/blob/v2.3.0/services/site/src/docs/content/config.mdx)

OpenAI lists OpenCode for ChatGPT sign-in and OpenCode documents the native ChatGPT route. A custom proxy still needs evidence of supported authorization and actual usage attribution. Route the user's subscription turn through their authorized Codex runtime, with a controlled environment and no inherited API-key override. A plan label or successful generic response cannot establish which allowance was used. Preserve quota, account and model denials. Record a separately authorized real turn and available redacted usage evidence for the highest Pro tier. If attribution cannot be observed, leave it unverified. [Sign in with ChatGPT](https://learn.chatgpt.com/docs/sign-in-with-chatgpt) · [OpenCode ChatGPT provider](https://github.com/anomalyco/opencode/blob/v2.3.0/services/site/src/docs/content/providers.mdx#chatgpt)

| REST driver | Native contract | Adapter and proof |
|---|---|---|
| Codex SDK 0.169.0 | Start/resume a thread; `runStreamed` starts the CLI for this turn and accepts an abort signal. Items can be cumulative snapshots or observations of tools that already ran. | Supply the intended Codex home and an allowlisted child environment. Bind user/workspace to native ID. Derive increments once, handle failure/completion distinctly and propagate stop. Check denied commands, filesystem and network policy in the deployed sandbox. [SDK source](https://github.com/openai/codex/tree/rust-v0.169.0/sdk/typescript/src) |
| OpenCode SDK 2.3.0 | `@opencode/sdk` embeds a runtime. Create a session with its approved location, subscribe before submitting its asynchronous prompt, scope events/permission replies, and explicitly interrupt. | Run a tenant-scoped instance with durable database and lifecycle management. Reopen the same native session after a worker restart. Bound queues and stop native work on explicit cancellation. Separate remote attachment through `@opencode/client` is optional. [SDK contract](https://github.com/anomalyco/opencode/blob/v2.3.0/packages/sdk/README.md) |
| Existing direct chat | The existing OpenAI-compatible REST data plane supports the configured profile, streaming and buffered replies. | Retain existing request/response semantics for callers. Route by explicit driver and model. Refuse self-referential OpenCode routes. Do not use direct chat as a silent fallback when a chosen SDK fails. |

Put one server-side SDK worker boundary behind Axum. A typed start, resume, send, stop and permission contract carries actor, workspace, driver, native session and turn correlation. Recommend local stdio IPC to a supervised worker with a bounded event queue, authenticated server-side session mapping and isolated execution contexts. Pin the worker runtime and native dependencies per release platform. Test interrupted and orphaned turns, shutdown, reconnect and recovery after worker failure. Resume must verify ownership and native state before accepting a follow-up. Keep browser bundles free of both server SDKs and credentials.

**Tool ownership affects actual plugin compatibility.** Codex SDK 0.169.0 accepts text/supported input items and reports native tool effects. It has no generic API to suspend on an arbitrary OpenCode function call and accept that host's result. For the initial Codex-backed provider, advertise accurate text capabilities, constrain native tools and reject unsupported tool requirements before work starts. Prove a normal OpenCode turn reaches this route; failure of the host to honor capabilities is a compatibility blocker. For intentional coding/tool workflows, spec an explicit OpenCode delegated tool whose invocation owns one entire Codex turn under user permissions and returns one result. Native effects may appear as telemetry and cannot be executed twice. If OpenCode-owned function calling is required, route that mode to a genuinely tool-capable provider and show the route to the user. Do not claim arbitrary function passthrough over the pinned Codex SDK. Test one authorized native tool and one denial on each applicable driver. ## Embedded chat, structured surfaces and packaging

**Adopt 007 and 009; adapt 008.** Use the upstream A2UI activity convention over AG-UI. Preserve existing text clients through an explicit protocol selection or versioned route. The new endpoint must accept a compatible run input and emit the expected camel-case identifiers, proper text ordering and an explicit run error. Represent surface snapshots with `ACTIVITY_SNAPSHOT`, a stable `messageId`, `activityType: "a2ui-surface"` and complete, validated operations in `content.a2ui_operations`. Replacement snapshots rebuild that activity's safe state. Applying replayed snapshots incrementally would duplicate edits. Keep React 19. Pin `@ag-ui/client` and `@ag-ui/core` at 1.0.5 and `@a2ui/react` and `@a2ui/web_core` at 0.15.0, using their `/v0_9` renderer/processor interfaces. Align the declared wire schema and catalog with that export. [AG-UI upstream snapshot implementation](https://github.com/ag-ui-protocol/ag-ui/blob/3416b86da4b3288e87f827c7f2759a7fa18b5231/middlewares/a2ui-middleware/src/activity-snapshots.ts) · [Published React declaration](https://unpkg.com/@a2ui/react@0.15.0/v0_9/index.d.ts)

Validate complete typed envelopes and bounded catalog operations before publishing. On the client, admit only registered accessible components/functions and approved URL schemes; keep plain assistant text inert. Scope state to user, thread, run and surface; handle creation, updates, deletion and idempotent replay. Keep usable text and the last safe surface after invalid input. For a keyboard activation validate the v0.9 `{version, action}` message, then adapt the action body into `forwardedProps.a2uiAction.userAction` on a new correlated AG-UI run. Recheck actor, component, surface lifecycle, permitted action and deduplication key on the server. Admin mutations require their own authorization. Test with the real browser reader and renderer, including truncated frames, unsupported versions and cross-session actions. [Action schema](https://github.com/a2ui-project/a2ui/blob/28e3d6bd4fb21a38be5abb0959bf73fd9708ffe0/specification/v0_9/json/client_to_server.json) · [Middleware action adapter](https://github.com/ag-ui-protocol/ag-ui/blob/3416b86da4b3288e87f827c7f2759a7fa18b5231/middlewares/a2ui-middleware/src/index.ts#L443-L480)

Prepare locked frontend dependencies once. Invoke the Vite 8 production build from Cargo `build.rs`, check its exit status and embed an asset table generated under `OUT_DIR`. Track authored sources, public assets, entry HTML, lockfile, tool configs and build-time env. Serve immutable hashed assets and revalidated HTML. Limit fallback to UI navigations; missing assets and unknown API endpoints retain error status. The final native binary serves chat and settings from an empty directory. The SDK-enabled release additionally ships or connects to its declared runtime and CLI; show a driver as unavailable if any prerequisite is missing. Exercise both a packaged web-only service and a packaged service that completes an actual SDK turn. Use the project's Impeccable brief, UI UX Pro Max guidance and shadcn/ui controls for streaming chat, keyboard operation, stop/recovery and separation of owner/admin actions. [Vite build](https://vite.dev/guide/build.html) · [Cargo build scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html)

## Dependency maintenance

The candidate file records a dated release and support assessment for each entry. The registries showed recent crate metadata updates for notify (November 15), rmcp (November 17) and jsonc-parser (September 27). These dates describe package activity, not support guarantees. The Codex and OpenCode SDK packages match the installed host versions. AG-UI client/core form a matching release pair. The published A2UI renderer exposes the older v0.9 profile even though upstream also documents newer wire versions.

The analysis recommends these packages for Spec. Production pins for the SDKs, renderer, protocol adapters and config editors remain conditional on current maintainer activity, advisory and platform checks, plus version-pair interoperability. Track each package's observed release evidence, upstream ownership and remaining support questions in [library candidates](library-candidates.json). The registry-query budget was exhausted, so absence of release-cadence evidence is recorded explicitly.
