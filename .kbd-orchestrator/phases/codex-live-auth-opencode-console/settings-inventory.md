# Chat and settings inventory

This is the scope of the embedded React console at kickoff `921868e`. Each control below needs a capability from the service indicating supported, enabled, effective value and source, change authority, and when the change takes effect. The existing CLI and TOML provide only part of this information. The shared-deployment browser acts on the **service host**. It cannot discover or edit a remote visitor's desktop. Provide downloadable configuration or a command for that desktop.

| Surface | Existing implementation | Required chat or administrative behavior |
|---|---|---|
| Deployment and access | Axum serves the network listener. `src/lib.rs` configures permissive CORS. No native chat/admin roles. | Identify service host, workspace, mode and actor. An authorized local owner can administer the machine. In shared mode, authorize chat, credential owners and admins at the API. Require same-origin/session and request-forgery protection for state changes. Separate host administration from personal login. |
| Service, logs and config | `--config` / `OPROXY_CONFIG`, default config directory, `setup config`, `config path/show`, TOML, env and serve flags. `HOST`, `PORT`, `RUST_LOG`, `/health`. | Show resolved source and precedence per value, including append/OR semantics, startup overrides, version, health, compile features and degraded integrations. Preview persisted edits. Label listener, mode, log and process-launch changes that need restart. Avoid writing ineffectual overrides. Redact secrets in diagnostics, diffs and logs. |
| Identity & routing | `--auth-path` / `CODEX_AUTH_PATH`, file/keyring loader, fallback `OPENAI_API_KEY`, `--backend-url` / `CODEX_BACKEND_URL`, `--wire-api` / `CODEX_WIRE_API`, `CODEX_DEFAULT_MODEL`. Backends are ChatGPT Codex, OpenAI Responses and OpenAI Chat Completions. | Display source/storage mode, per-user owner, active profile, model access, generation, status, last pickup and retry window. Separate reload from managed refresh and sign-in-required. Handle custom home/path, account switch, keyring-only, external tokens and API keys. Separate upstream selection and trusted destinations from login. Display which settings are live. |
| Chat and models | `POST /v1/chat/completions`, `GET /v1/models`, `src/openai.rs`, `src/proxy.rs`, `src/model_catalog.rs`. | Conversation, model, system instructions, streaming or buffered reply, supported message parts and tool results. Advanced controls cover output limit, temperature, top-p, stop, tool schemas, choice and parallel calls where supported. Distinguish model defaults/aliases and unavailable controls by profile. Derive owner server-side. Show usage when supplied, stop, partial output, errors and recovery. |
| SDK harnesses | Existing direct REST transport, no SDK-powered REST turn/session endpoint. | Choose Codex SDK or OpenCode SDK per conversation. Show native runtime/version/reachability, available models, approved workspace, tool/approval capability and effective sandbox. Retain existing direct REST access. Bind resume, stop and approval to authenticated owner and native session. Surface missing runtime or rejected permission without silently switching driver. |
| OpenCode on this host | `src/cli/setup.rs`, `opencode.json`, `plugin/`. Static V1 provider and native V1 plugin, provider overrides and shell env injection. Existing setup defaults to project, accepts `--global`, port, dry-run and force. Native Codex plugin is separately declared in `.codex-plugin/plugin.json` with a local marketplace manifest. | Detect executable/version and actual JSON/JSONC precedence. Offer only OpenCode 2.x native plugin or V2 static provider setup. Report unsupported or mixed V1 configurations with a separate V2 export. Show plugin or provider mode, project/global scope, plugin reference, provider ID, proxy address, model override and health. Preserve intentional overrides. Validate local and packed plugin registration and discover the global install from an unrelated directory. Distinguish installing the Codex marketplace plugin, registering MCP, or merely selecting a chat driver. |
| Safe machine configuration | Setup currently merges parsed JSON and writes directly. A parse failure can discard an existing file. The OpenCode dry-run prints proposed provider data. | Preview the actual redacted merge at the resolved target. Use the client schema, scoped file access, safe executable paths and ownership markers. Retain JSONC comments/TOML and unrelated entries. Refuse invalid/unwritable or concurrently edited inputs. Provide atomic apply, idempotent reapply and conflict-aware undo/removal. Show any client reload requirement. On containers or remote hosts, show export instructions when local apply is unavailable. |
| ACP clients | Exclusive `serve --acp-stdio` mode, dedicated stdout for protocol, session/new and streamed text prompts. Basic capabilities and limited handling of upstream failures. | Generate a Zed custom external agent in `agent_servers` using the installed binary and `serve --acp-stdio`. Offer a second documented client such as JetBrains AI Assistant and a generic stdio command for others. Preview absolute executable, arguments, allowed environment, working directory and status. Confirm initialization, session creation, a prompt and update. Show only verified support for cancel, resume, permissions and tool calls. Keep ACP configuration separate from the editor's MCP server registration. [Zed](https://zed.dev/docs/ai/external-agents) · [JetBrains](https://www.jetbrains.com/help/ai-assistant/acp.html) |
| Proxy as MCP server | `serve --mcp-stdio`, optional companion `--mcp-http-port` / `MCP_HTTP_PORT` and `POST /mcp`. `setup mcp --opencode/--claude` emits HTTP config. `.mcp.json` launches stdio. Tools are `chat_completion`, `list_models`, `check_auth` and `set_model`. | Detect supported clients and version-specific schemas. Candidate targets are Codex CLI, Claude Code, OpenCode 2.x, Zed and VS Code/Copilot. Show each client's supported transport, scope, launch command or endpoint and verification. Verify tools/list plus a benign call with a real client at a pinned protocol revision. Protect HTTP binding and account metadata. Current `list_models` has its own catalog and `set_model` supplies advice. Represent their actual behavior. |
| Tool imports | `[mcp].config_path`, static `[[tool]]` definitions, optional `[sources].claude_code` logs server names without importing their schemas. Local schema injection augments REST request tools. | Show source, schema, collision behavior and effective tools per driver. Indicate which runtime actually executes calls. Keep imported schemas and external client registration in separate settings. |
| AG-UI and A2UI | `POST /ag-ui/stream` streams text. A2UI JSON can appear in text. | Show A2UI wire 1.0, AG-UI 1.0.5, the loaded renderer and catalogs, structured event envelope, allowed catalog, renderer status and limits. Validate a complete typed message and render accessible controls in chat. Scope surface updates, deletes and action replies to the originating session. Provide accessible text/error fallback and reject unsupported catalog entries or callbacks. |

| Skills | `[skills].dirs`, `max_injected`, `PROXY_SKILLS_DIRS`, `PROXY_SKILLS_MAX` and CLI list, validate and selection test. Indicate startup loading vs per-request behavior, env precedence and ignored settings until reconciled. Use server-approved directories. |
| Webhooks | `[hooks].config_path`, `--hooks-config` / `PROXY_HOOKS_CONFIG`. Failed loading falls back to null hooks. | Display configured vs actually emitted events by mode, redacted destinations, effective delivery state and last failure if observable. Changes affect outbound data. Limit setup and any bounded test delivery to an authorized admin, using trusted destinations and synthetic content. |
| Memory and retrieval | Cargo `memory` feature, `[memory].enabled`, database path and embedding model, API key for embeddings, optional document create/list/delete and search endpoints under `/v1/memory`. Startup can fall back to a no-op store. | Distinguish omitted at build, disabled, failed DB, absent embedding credentials and ready. Identify source and cost boundary for embeddings separately from Pro. Admin settings display effective path/model. Authorize document operations, search, injection and delete by owner on the server. A supplied scope header or bare document ID is insufficient in shared mode. |
| Packaging & process topology | HTTP server plus optional MCP HTTP listener, exclusive MCP or ACP stdio early returns (MCP first if both requested). A stdio-only process has no web console: configure its launch from an HTTP management instance or export the command. Distinguish embedded assets, SDK runtime dependencies and host-owned services. Disable unavailable controls with a reason. |
