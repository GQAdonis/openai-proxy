# Design

## Context

`src/lib.rs` mounts `POST /ag-ui/stream`. `src/agui.rs` emits five text events, serializes some identifiers in snake case, and can finish after an upstream stream failure. `Dockerfile` builds a Rust binary with no frontend stage. `PRODUCT.md` covers a developer who manages their own proxy and shared users who have distinct chat, credential-owner and service-admin permissions.

## Goals / Non-Goals

**Goals:** Make the shipped service usable for streaming chats and settings in both deployment modes. Give typed AG-UI clients and the real React renderer a versioned, testable contract. An authorized user's keyboard activation must have a verifiable effect in the originating conversation.

**Non-Goals:** The SDK and identity changes own native session execution and credential refresh. The admin change owns host detection, schema, writers, authorization and apply/undo. This change consumes those contracts. Remote component registries and unrestricted generated callbacks are outside the selected surface catalog.

## Decisions

### Build and route the shipped application (UI-1)

Create `frontend/` with React 19, React DOM 19, TypeScript and Vite 8. Pin Node, the package manager and exact dependency resolutions in the build manifest/lock. Prepare dependencies explicitly in developer and CI setup and the Docker builder. Use a locked install (for npm, `npm ci`). Cargo `build.rs` invokes the local production build, e.g. `npm run build -- --outDir <OUT_DIR>/console --emptyOutDir` from `frontend/`, checks its exit status, checks that index and referenced assets exist, and generates a stable path, content-type and `include_bytes!` asset table under `OUT_DIR`. Rust includes the generated table. Cargo rerun inputs cover source and public directories, HTML, package manifest, lockfile, tsconfig, Vite config and build-relevant environment. Output and dependency directories are outside that input set. Fail the current build if the frontend fails, even when an older build emitted an index. The final Docker stage copies the binary. SDK-enabled deployments separately provision compatible driver runtimes. Use `cargo build --release --locked` and preserve the optional `memory` build and protocol-only stdio entry points. [Cargo build scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html) · [Vite build](https://vite.dev/guide/build.html)

Set Vite `base` to `/ui/`. Redirect `/ui` to `/ui/`. Serve same-origin index and deep links such as `/ui/settings` only for GET/HEAD HTML navigations. Serve only actual assets with correct MIME, length and immutable caching for fingerprinted names. Revalidate HTML. Keep absent assets, unknown API/protocol paths, bad methods and missing non-navigation requests as genuine errors. The standard HTTP executable serves these routes from an empty working directory with no JS runtime or dev server.

### Chat from the service API (UI-1)

Use the Impeccable product brief, UI UX Pro Max keyboard/accessibility guidance and locally composed shadcn/ui components. Give the transcript, labelled composer, model and driver choices, Stop, settings link, status and focus order distinct roles. Preserve scroll position for readers reviewing older messages, offer jump-to-latest, and group completion/error announcements. Keep controls usable in a narrow viewport and with reduced motion. Model choice, system instructions, advanced sampling, tools and usage depend on effective driver/profile capabilities.

Start with `POST /api/v1/conversations`, create a turn at `POST /api/v1/conversations/{id}/turns`, consume `GET /api/v1/conversations/{id}/turns/{turnId}/events` and cancel at `POST /api/v1/conversations/{id}/turns/{turnId}/cancel`. The service binds actor, workspace, driver, native session and turn. Use the last accepted monotonic event ID on reconnect. If the replay window is gone, show an explicit recovery state. Never create a turn merely to reconnect. Present cancel requested, acknowledged stop, complete, failure before text, partial failure and unavailable driver distinctly. Retain the transcript and return keyboard focus to a predictable place. Retry is an explicit user decision subject to the driver's replay/side-effect policy. Protocol projections and tool observations reuse the driver owner's run.

### Settings from effective service state (UI-1)

Fetch `GET /api/v1/admin/settings` only for an authorized actor. Each visible option uses the management contract for its supported/enabled/degraded state, effective/redacted value and source/precedence, scope/target, allowed actor, and apply timing or reason for being unavailable. For chat-only viewers fetch `GET /api/v1/me/connection`. Render its redacted connection state and permitted drivers, available controls and allowed recovery actions. Derive identity from the session and never query the admin endpoint to populate this screen. Authenticated local ownership, personal credential ownership, and shared service administration are distinct scopes. Resolved paths and commands refer to the service host. Offer export for visitor-owned or read-only targets. For durable writes show the actual redacted preview, target, effective impact and conflict from `POST /api/v1/admin/config/preview`, `/apply` and `/undo` under the same prefix. Mutations require an authorized session and request-forgery protection. Browser storage, rendered values, diagnostics and request payloads exclude upstream credentials.

Each row below describes what to display when supplied by the service. The sibling admin spec owns the option schemas, permission enforcement and persistence. The source/effect column describes how to label actual capability data, including masked or degraded settings. See the [phase inventory](../../../.kbd-orchestrator/phases/codex-live-auth-opencode-console/settings-inventory.md).

### Versioned AG-UI and released A2UI 1.0 (SURFACE-1)

Keep the existing `POST /ag-ui/stream` demo as an independent text path. Add `POST /api/v1/ag-ui/stream` with validated `RunAgentInput`, `text/event-stream` and camelCase `threadId`, `runId` and `messageId`. Pin the latest released compatible `@ag-ui/client` and `@ag-ui/core` at 1.0.5 (verified November 19, 2026). Use `HttpAgent` and its subscriber to consume complete typed events and `@ag-ui/core/schemas` for validation. Emit ordered message start/content/end and one terminal `RUN_FINISHED` or `RUN_ERROR`. A lost transport without a terminal event is interrupted. A REST replay and its AG-UI projection reuse the same logical turn and executor.

Use a stable `messageId`, `ACTIVITY_SNAPSHOT`, `activityType: "a2ui-surface"`, `replace: true` and a complete `content.a2ui_operations` array. The published `@ag-ui/a2ui-middleware` 0.0.16 implements this convention. Its inline catalog must declare `protocolVersion: "1.0"` with a matching `defaultCatalogId`, since missing or unrecognized declarations select its older default. Rust can project this same envelope without running a second agent. [Middleware release](https://registry.npmjs.org/@ag-ui/a2ui-middleware/-/a2ui-middleware-0.0.16.tgz) · [Snapshot contract](https://github.com/ag-ui-protocol/ag-ui/blob/3416b86da4b3288e87f827c7f2759a7fa18b5231/middlewares/a2ui-middleware/src/activity-snapshots.ts)

#### Validate the stable wire and adapt the published renderer

Require the exact wire value `version: "1.0"`. Bundle the normative agent-to-renderer, renderer-to-agent and referenced common schemas at revision `28e3d6bd4fb21a38be5abb0959bf73fd9708ffe0`. Prevalidate each complete operation on the server and in the browser and apply the local catalog policy before allocating a renderable surface. Reject old or unknown versions and unsupported RPC operations. Permit the bounded, ordered `createSurface`, `updateComponents`, `updateDataModel` and `deleteSurface` lifecycle, with approved component and action names and allowed resource URLs. Bundle a local policy-filtered catalog for `https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json`. A catalog identifier never initiates a network fetch. [Stable version manifest](https://github.com/a2ui-project/a2ui/blob/28e3d6bd4fb21a38be5abb0959bf73fd9708ffe0/specification/versions.json) · [Normative schema files](https://github.com/a2ui-project/a2ui/tree/28e3d6bd4fb21a38be5abb0959bf73fd9708ffe0/specification/v1_0/json)

Pin `@a2ui/web_core` and `@a2ui/react` at 0.15.0, published November 2. Import `A2uiSurface` from `@a2ui/react`, `MessageProcessor` from `@a2ui/web_core` and `basicCatalog` from `@a2ui/web_core/catalogs/basic/v1`. The React root consumes a resolved surface model. Its peer range includes React 19. The processor's runtime registers its 1.0 adapter alongside older adapters. The `@a2ui/web_core/v1_0` export supplies `AgentToRendererMessageSchema` and `RendererToAgentMessageSchema` for the package's internal representation. Explicitly type `MessageProcessor<ReactCatalogComponent>` where the published constructor cannot infer the React surface type, and typecheck the locked app. [React tarball](https://registry.npmjs.org/@a2ui/react/-/react-0.15.0.tgz) · [Web core tarball](https://registry.npmjs.org/@a2ui/web_core/-/web_core-0.15.0.tgz) · [Upstream rendering test before publication](https://github.com/a2ui-project/a2ui/blob/c1a8de786623d30ec6372682f7a745c34a9a4a1a/typescript/renderers/react/tests/v1_0_surface.test.tsx) · [Subsequent typing fix](https://github.com/a2ui-project/a2ui/commit/8bf644a37d680a227296b8c0849a7f4b328b8b73)

On November 11, the project changed four reserved component fields in the stable wire. The published package's generated common schema still uses the earlier spellings. In a copy of a validated wire operation, adapt only these field positions and policies for the pinned package. Preserve the stable canonical snapshot for replay and audit. [Upstream schema and SDK amendment](https://github.com/a2ui-project/a2ui/commit/24d1bf9c830071f74c9c908433e73cc6cbe0aa33)

| Stable component field | Renderer projection and policy |
| --- | --- |
| `@accessibility` | Map permitted accessibility fields on `updateComponents.components[]` entries to the renderer's `accessibility`. Resolve supported label/description bindings against authorized surface data. Bind their values to the actual interactive element if the packaged catalog component omits them. Prevent hidden focusable actions and excessive live announcements. Verify the browser accessibility tree after creation and updates. |
| `@catalogId` | At a component-envelope position map only the approved bundled catalog ID to `catalogId`. Leave the protocol's existing `createSurface.catalogId` field intact. Reject unknown IDs. |
| `@metadata` | Initial catalog permits no component metadata extensions. Reject unapproved metadata. Any future explicitly permitted extension must be validated at its component-envelope position before mapping it to `metadata`. |
| `@checks` | Initial catalog permits no arbitrary check or function execution. Reject unsupported checks at the Checkable position. A future permitted declarative check must have a local validator and validated arguments before mapping to `checks`. |

Reject collisions or unprefixed reserved fields at component-envelope positions in this catalog. Never rename recursively. Preserve ordinary user data, `@path` and `@call` expression syntax, action context, and arbitrary data-model keys through the projection. Only expressions/functions that the policy admits may execute. Disable general-purpose remote navigation, raw HTML, scripts, local/remote RPC and privileged callbacks. Use finite byte, depth and count limits on input, candidate state and replay. Key state by actor, thread, originating run and surface. Rebuild a fresh candidate surface per complete replacement snapshot, publish it atomically and retire superseded state. Duplicate delivery converges. Invalid input leaves the last safe surface and text available. Keep focus stable or move to an announced, usable destination after deletion.

#### Reauthorize the user's action

On a genuine control activation, handle the processor's action callback (or subscribe to `processor.model.onAction`), create `{version:"1.0",action:{name,surfaceId,sourceComponentId,timestamp,context}}` and validate against the stable renderer-to-agent schema and local action policy. Handle optional `userMessage` and `metadata` only as permitted data. On the correlated AG-UI run send the approved action body through `forwardedProps.a2uiAction.userAction`. Middleware accepts optional action fields, so the service revalidates required fields and binds the action to the authenticated session, originating run and live component. Authorize the named action and bounded context, check origin/CSRF and deduplicate before invoking a handler. Timestamp supplies no authority. Replay yields the prior authorized outcome. Stale, foreign or deleted controls, administrative changes and tool/host execution requests have zero effects. [Wire action schema](https://github.com/a2ui-project/a2ui/blob/28e3d6bd4fb21a38be5abb0959bf73fd9708ffe0/specification/v1_0/json/renderer_to_agent.json) · [AG-UI action adapter](https://github.com/ag-ui-protocol/ag-ui/blob/3416b86da4b3288e87f827c7f2759a7fa18b5231/middlewares/a2ui-middleware/src/index.ts#L443-L479)

## Risks / Trade-offs

Node and frontend package acquisition add build prerequisites. Pin and provision the builder separately from the shipped web runtime. A native SDK turn can require a sidecar or CLI even if serving the embedded files succeeds. Exercise each boundary independently. The A2UI libraries are pre-1.0. Keep the wire profile and package exports locked and make unsupported profiles visibly degrade to text. An event replay can arrive after an account switch or a deletion. Check current ownership and lifecycle before sending, replacing or acting.

At B4 run the shipped binary through `openai-proxy serve` outside the checkout and launch the final release image. Observe the browser, wire and independent effect counter.
